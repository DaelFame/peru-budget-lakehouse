# BITÁCORA DE PROYECTO: PERU-BUDGET-LAKEHOUSE

## 1. STACK TECNOLÓGICO (Local Lakehouse Stack)

Para este proyecto, priorizamos el rendimiento multihilo (aprovechando el Ryzen 9) y la portabilidad sin dependencias de servidores.

* **Gestor de Entorno:** `uv` (Fastest Python package manager). Reemplaza a pip/conda por su velocidad y capacidad de generar entornos reproducibles con `uv.lock`.
* **Motor de Procesamiento:** `Polars`. Motor de DataFrames escrito en Rust. Utiliza evaluación perezosa (Lazy API) y paralelismo nativo.
* **Motor de Consulta SQL:** `DuckDB`. Base de datos analítica (OLAP) in-process. Permite ejecutar SQL complejo directamente sobre archivos Parquet con rendimiento de clase mundial.
* **Formato de Almacenamiento:** `Apache Arrow / Parquet`. Formato columnar que reduce el espacio en disco y acelera las lecturas de datos en comparación con CSV o Excel.
* **Entorno de Desarrollo:** `VS Code` + `Jupyter Notebooks`. Para experimentación interactiva y prototipado de pipelines.

---

## 2. ARQUITECTURA DE DATOS (Medallion Architecture)

El proyecto se organiza en capas lógicas para asegurar la trazabilidad y calidad del dato:

* **CAPA BRONZE (Raw):** Ingesta de datos crudos. Archivos CSV/Excel tal cual se descargan del MEF. Inmutables.
* **CAPA SILVER (Cleansed):** Datos limpios y normalizados. Nombres de columnas en snake_case, tipos de datos corregidos (fechas, decimales) y filtros iniciales. Formato: Parquet.
* **CAPA GOLD (Curated):** Modelo Estrella (Star Schema). Tablas de Dimensiones y Hechos optimizadas para analítica financiera y BI. Formato: Parquet.

## 4. COMANDOS DE INICIALIZACIÓN (Quickstart)
Para qué sirve cada herramienta en tu "Local Lakehouse"?
polars: Tu motor principal. Procesará los 8.5 GB en paralelo usando todos tus hilos de CPU. Es el reemplazo moderno de Pandas.

duckdb: La "navaja suiza" de SQL. Te permitirá hacer consultas analíticas ultra rápidas sobre tus archivos Parquet sin necesidad de instalar una base de datos real.

pyarrow: Es el motor que permite a Polars y DuckDB escribir y leer archivos Parquet de forma eficiente. Es indispensable para la capa Silver y Gold.

connectorx: (Opcional pero recomendado) Es la librería más rápida para leer datos de SQL hacia Python si en el futuro decides traer datos de una fuente externa.

notebook e ipykernel: Necesarios para que VS Code pueda ejecutar tus archivos .ipynb (Jupyter) usando el entorno virtual que gestiona uv.

```

---

## 5. FILOSOFÍA DE TRABAJO

1. **Code-First:** El pipeline se define en código (Python/Polars), no en herramientas GUI.
2. **Performance:** Cada transformación debe ser evaluada mediante el plan de ejecución de Polars (`df.explain()`) para maximizar el uso de los 16 hilos del procesador.
3. **No-DB:** No se requiere una instancia de base de datos activa (Postgres/MySQL); el archivo es la base de datos.
